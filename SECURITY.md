# Security policy

## Reporting a vulnerability

Use GitHub private vulnerability reporting or open a private Security Advisory in the repository Security tab. Do not disclose an unpatched vulnerability in a public issue, pull request, discussion or code comment.

Include affected versions, reproducible steps, impact and a minimal proof of concept. Do not include real user data, credentials, uploaded documents or destructive payloads.

## Secrets and privacy

Never commit local environment files, service-role keys, AI or payment credentials, deployment tokens, user identifiers, offer documents or production exports. Validation must use public values, placeholders or isolated test data.

## Scope

Security reports are welcome for authentication, authorization, private-route access, upload handling, payment/webhook verification, secret exposure, cross-tenant data access and deployment boundaries. Product estimates are decision support and are not engineering certification.
